# T1566.001 - Phishing: Spearphishing Attachment

## Metadata
- **Technique ID:** T1566.001
- **Name:** Phishing: Spearphishing Attachment
- **Tactic(s):** Initial Access
- **Platform(s):** Windows, macOS, Linux, SaaS
- **Permissions Required:** User
- **Data Sources:** Email Gateway, File Monitoring, Network Traffic, Process Monitoring
- **Version:** 1.0
- **Confidence Level:** high
- **Created:** 2024-01-15
- **Last Updated:** 2024-12-15

## Description
Adversaries send spearphishing emails with malicious attachments to gain initial access. The attachment exploits a vulnerability or uses social engineering to execute code. Common file types: .doc/.docx (macros, DDE, OLE), .pdf (JavaScript, exploits), .exe/.scr/.zip (executables), .lnk (shortcuts), .iso/.img (disk images), .one (OneNote), .html/.htm (HTML smuggling).

## Detection
### Detection Logic
Spearphishing attachments are detected at multiple layers:
1. **Email Gateway:** Attachment sandboxing, reputation, YARA, AV
2. **Endpoint:** File write, process execution, macro execution, exploit behavior
3. **Network:** C2 callbacks, file downloads post-exploitation
4. **User Reporting:** Phish reporting mailbox

### Data Sources Required
| Data Source | Components | Coverage |

| Endpoint (EDR) | File creation, process tree, command line, API calls | High |
| Network | DNS, HTTP, TLS, proxy logs | Medium |

### Splunk/Elastic/KQL Queries

```splunk
| stats count min(_time) as earliest max(_time) as latest by Computer, New_Process_Name, Parent_Process_Name, CommandLine
```

```kql
# KQL (Sentinel/Defender): Suspicious email attachment behavior
DeviceProcessEvents
| where InitiatingProcessFileName in~ ("WINWORD.EXE", "EXCEL.EXE", "POWERPNT.EXE", "OUTLOOK.EXE")
| where FileName in~ ("cmd.exe", "powershell.exe", "wscript.exe", "cscript.exe", "mshta.exe", "rundll32.exe")
| project Timestamp, DeviceName, InitiatingProcessFileName, FileName, ProcessCommandLine, InitiatingProcessCommandLine
```

### False Positives
- Legitimate macros in finance/HR documents (mitigate: signed macros, trusted locations)
- Administrative scripts launched from Office (mitigate: allowlist)
- Software installers from email (mitigate: block .exe/.msi in email)

### False Negatives
- Exploits that don't spawn child processes (e.g., memory-only)
- HTML smuggling (payload in .html attachment)
- OneNote attachments (.one) with embedded scripts
- Password-protected archives bypassing gateway scanning

### Specific Mitigations for This Technique
- **Email Gateway:** Block high-risk extensions (.exe, .scr, .bat, .cmd, .com, .pif, .hta, .js, .vbs, .wsf, .jar, .lnk, .iso, .img)
- **Office Configuration:** Disable macros by default; enable "Block macros from running in Office files from the internet"
- **Protected View:** Force for all email attachments
- **Application Guard:** Use for Office/Edge isolation
- **User Reporting:** Dedicated phish mailbox with automated analysis

## Notes & Analysis
Spearphishing attachment remains the #1 initial access vector despite decades of defenses. Key trends:

1. **Format Evolution:** .doc/.pdf → .iso/.img → .lnk → .one → .html (HTML smuggling) → .zip with .lnk inside
2. **Macro Decline:** Microsoft blocking internet macros forces shift to exploits, LNK, HTML, ISO
3. **Living Off The Land:** Attachments increasingly use built-in tools (mshta, rundll32, cscript) not custom EXEs
4. **Password-Protected Archives:** Bypass gateway scanning; user enters password from email body
5. **OneNote (.one):** Emerging format (embedded files/scripts, no macro warning)
6. **Shortcuts (.lnk):** Execute commands directly, no exploit needed

**Detection Strategy:** Layered approach essential - gateway + endpoint + network + user reporting. No single layer catches all variants.
